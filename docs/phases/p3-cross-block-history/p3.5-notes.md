# P3.5 HardBreak / CodeBlock Multi-line 实施说明

本文件记录 P3.5 实施中的短期验证事实，阶段完成后由 `progress.md` 与 `architecture.md` 接管长期状态。

## Canonical contract

ADR 0004 已接受：

```text
soft wrap          → frontend-only visual geometry
Paragraph LF       → canonical HardBreak
Heading LF         → canonical HardBreak
CodeBlock LF       → canonical code newline
```

canonical line ending 统一为 LF。CRLF / CR 只允许存在于平台输入边界，进入 canonical text 前规范化为 LF。

## 当前实现切片

- Runtime 提供 `EditIntent::insert_line_break()` 语义构造器；当前编译到 isolated text replacement，因此复用既有 `ReplaceText` mapping / inverse / StoredMarks / history contract，同时不给 GPUI 暴露 `PasteText` 这一实现选择。
- `Shift+Enter` 映射为 HardBreak action，向当前 inline block 插入一个 LF。
- 普通 Paragraph / Heading 的 `Enter` 继续 `SplitBlock`。
- `CodeBlock` 的 `Enter` 改为插入 LF，不创建 sibling block。
- `CodeBlock` 的 Tab 插入四个可见空格，不触发 list conversion / list indent；Shift-Tab 在本切片不执行 list structural command。
- CodeBlock plain-text paste 保留多行并执行 `CRLF / CR → LF`；普通富文本 plain-text fallback 继续把 line break 折叠为空格。
- structured clipboard 不增加特殊格式，LF 作为 inline text 原样 round-trip。

## 仍需验证 / 收口

- Runtime：HardBreak / CodeBlock newline 的 selection、history、StoredMarks、undo/redo 回归。
- Core：证明既有 `ReplaceText` mapping / inverse 对 LF 无特殊缺口，不新增 Core step。
- GPUI：multi logical-line layout、Home/End、Up/Down、hit-test、selection 在 LF 两侧的回归。
- CodeBlock persistence / plain-text paste round-trip。
- Windows 实机：Paragraph Shift+Enter、CodeBlock Enter/Tab/paste、IME 与多行导航。
- `architecture.md` / `progress.md` 最终同步。
